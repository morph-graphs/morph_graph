# baselines/egorag: EgoRAG (EgoButler) on EPIC-Morph

[EgoRAG](https://github.com/EvolvingLMMs-Lab/EgoLife) is the retrieval half of EgoButler, the baseline system of
EgoLife (Yang et al., CVPR 2025, arXiv 2503.03803; code under the S-Lab License 1.0, non-commercial; the EgoGPT
folder says Apache-2.0). EgoGPT captions every 30 s clip from video and audio; the captions are indexed by
sentence and summarised at 10 min, 1 h and day level; a question is answered by letting an LLM pick a time range
from the summaries, retrieving the 3 best-matching caption sentences in it, extracting evidence from those clips'
captions and answering from the evidence.

## Read first

**The method runs as released, with its own models, not our local backbones.** The rule for this port: run the
released code as it is, and change only what is needed to run it and to keep a question from seeing video after
its `t_ask`. Everything after the captions is a **paid API call**.

| step | model | where it runs |
|---|---|---|
| caption per 30 s clip (1 fps frames + audio) | EgoGPT-7b, `lmms-lab/EgoGPT-7b-EgoIT-EgoLife` (EgoIT-99K + EgoLife day 1) | local, one 48 GB GPU |
| sentence index | OpenCLIP ViT-B-32 `laion2b_s34b_b79k` text encoder (Chroma's default embedding function) | local, CPU |
| 10 min and day summaries | GPT-4o (`call_gpt4`) | **paid**: `OPENAI_API_KEY` |
| 1 h summaries | DeepSeek (`call_deepseek`; DeepSeek-R1 in the released code) | **paid**: `DEEPSEEK_API_KEY` |
| per question: day and time-range choice, evidence per retrieved clip, answer | GPT-4o (`call_gpt4`); the paper: "the final response is universally generated by GPT-4o" | **paid**: `OPENAI_API_KEY` |

What differs from the release, all of it:

1. **Keys (`EgoLife.patch`).** As released only the Azure branches of `egorag/utils/util.py` can run: the
   `OPENAI_API_KEY` branch calls `openai.ChatCompletion` (removed in the openai 1.x the package pins, and it
   names `gpt-4`), and the `DEEPSEEK_API_KEY` branch indexes the response object like a dict (and names
   `deepseek-chat`). The patch makes the plain-key branches work: GPT-4o through the OpenAI API (model `gpt-4o`,
   the same request as the Azure branch), DeepSeek through `https://api.deepseek.com`, and it logs each call's
   returned model id and token usage. The Azure branches are unchanged and still take precedence when their
   variables are set. `run_egorag.sh` applies the patch to the submodule's files once.
2. **DeepSeek-R1 is no longer offered by DeepSeek's API.** Its pricing page (read 2026-11-13) lists only
   `deepseek-flash` (DeepSeek-V4.1-Flash) and `deepseek-v4-pro` (DeepSeek-V4-Pro), both thinking by default;
   neither `deepseek-reasoner` nor R1 is named. The hour summaries therefore ask for `deepseek-v4-pro`
   (`EGORAG_DEEPSEEK_MODEL` changes it; with upstream's Azure variables, `DEPLOYMENT_NAME`, default
   `DeepSeek-R1`). **This is a model substitution we could not avoid on a plain DeepSeek key**, and it has not
   been called yet: whether `max_tokens=2048` (upstream's) leaves room for the answer after the model's
   reasoning is unknown. `runs.jsonl` records the model id the API returned.
3. **One video is one EgoLife day starting at 10:00:00.** EgoRAG works in EgoLife's clock (`DAYn`, `HHMMSSFF`)
   and only handles 8-digit times (it reads the hour from the first two digits and asks the LLM for `[\d{8}]`),
   so video second 0 is `DAY1 10000000`. The LLM sees these clock times; answers record video seconds.
4. **The cutoff.** A question asked at `t_ask` is asked at clock(floor(t_ask)), as in the MERIT port. Upstream
   already uses only hour summaries that ended by then and summarises the later captions (up to the question)
   itself. The time range the LLM then returns is not checked upstream; here every retrieval is also limited to
   clips that ended by the question time (a clip's sentences all carry the clip's end time), and the returned
   clips are asserted to be.
5. **Retrieval query.** EgoLifeQA questions carry hand-written `keywords`, which upstream embeds as the query.
   EPIC-Morph has none: the question text is the query.
6. **Audio.** Upstream's EgoGPT wrapper slices the audio with the `HHMMSSFF` integers as seconds, which gives an
   empty slice (silence) for every clip. The paper captions from video and audio, so the clip's own audio is
   passed (`caption_clips_egogpt.py --audio silent` gives the released behaviour).
7. **Captions through a file.** Captions are written to JSON and indexed with `create_database_from_json`
   (upstream's "Method 1"), so they are a memory file and resumable.
8. **Failures are counted.** Upstream drops a question it fails on (its accuracy is over the rest) and answers
   at random after an API error. Here a failed question is retried three times and then stays unanswered (`qa`
   exits 2; rerun), so every question of the bank is counted.

Kept as released: text evidence (`main.py` calls `extract_evidence(..., modality="text")`: the LLM reads the
retrieved clips' captions; EgoGPT does not watch the clip again), upstream's prompts, temperatures (0.7 to 0.9
for summaries and range choice, 0.1 for answers; so reruns differ), top 3 sentences, `max_tokens`. With one day
per video the day level is trivial: the LLM is still asked for the day. There is no blind stage: the method has
no local answer model to probe. One arm, `egogpt_gpt4o`.

## Layout

| path | what |
|---|---|
| `EgoLife/` | submodule: upstream [EvolvingLMMs-Lab/EgoLife](https://github.com/EvolvingLMMs-Lab/EgoLife) at `7a97157` (not a fork) |
| `EgoLife.patch` | our only change to upstream: the plain-key API branches of `EgoRAG/egorag/utils/util.py` and the usage log |
| `epic/prepare_clips.py` | one HD-EPIC video -> 30 s clips with audio (448 px) and the clip list, in EgoLife's clock |
| `epic/caption_clips_egogpt.py` | the memory, step 1: an EgoGPT caption per clip (upstream's wrapper and prompt) |
| `epic/build_memory.py` | step 2: the Chroma index (upstream `create_database_from_json`), then the summaries (upstream `gen_event`, paid) |
| `epic/run_qa.py` | answers one video's questions of a bank (upstream `RagAgent.query`, `extract_evidence`, `get_answer`; paid) |
| `epic/estimate_api.py` | counts the paid calls and tokens of a video's build and questions from its captions, without calling anything |
| `run_egorag.sh` | one video, one stage (prep, build, qa, upload, all) |
| `env/` | the environment, pinned: `requirements*.txt`, `install_requirements.sh` (shared by the image and `setup_env.sh`), `check_env.py` |
| `docker/` | the image (`Dockerfile`), `build.sh`, `run.sh` (one job in a container; the job board's entry point), `image_tag.sh` |
| `../merit/epic/prepare_epic.py` | (MERIT's) the bank -> EgoLifeQA question rows, reused here |
| `../common/hf_results.py` | (shared) upload a video's results to the Hugging Face dataset, or fetch its memory |

## Running

**Off our clusters, run only in the Docker image** (rule in `AGENTS.md`): `ghcr.io/morph-graphs/egorag:<arm>-<env
hash>`, built from `docker/Dockerfile` by `.github/workflows/baseline-images.yml`. The image holds the environment
(CUDA 12.1 toolkit, which deepspeed needs to import; a new enough sqlite for Chroma through `pysqlite3`); the code
is the mounted checkout of `main` with `git submodule update --init baselines/egorag/EgoLife`.

```bash
docker pull ghcr.io/morph-graphs/egorag:$(bash baselines/egorag/docker/image_tag.sh)
export EPIC_MORPH_DIR=<epic-morph checkout>      # videos: $EPIC_MORPH_DIR/data/HD-EPIC/videos, or set HDEPIC_VIDEOS
export OPENAI_API_KEY=... DEEPSEEK_API_KEY=...   # in the shell only: never in a file or on a command line
EGORAG_GPU=0 bash baselines/egorag/docker/run.sh build P05-20240425-201444 egogpt_gpt4o      # captions (GPU), index, summaries (paid)
bash baselines/egorag/docker/run.sh qa     P05-20240425-201444 egogpt_gpt4o batch10_agree2   # paid, no GPU
bash baselines/egorag/docker/run.sh upload P05-20240425-201444 egogpt_gpt4o
```

- **Without a key nothing is called**: `build` makes the captions and the index and stops with exit 4, naming the
  missing key; `qa` exits 4. So the GPU part can be done first, by anyone, and the paid part later from the same
  results folder (or from the dataset, after `upload` of a finished memory).
- `EGORAG_LIMIT=5` answers only 5 questions (a first paid smoke test: a few cents).
- `docker/run.sh` mounts this checkout at `/repo`, the epic-morph checkout at `/epic-morph`, the videos at
  `/videos` and the Hugging Face cache (`EGORAG_HF_CACHE`, default `~/.cache/huggingface`) at `/hf`; keys are
  handed to the container by name. `EGORAG_RUNTIME=apptainer` runs the same image with Apptainer. The job board
  (`coord/worker.py`) calls it with `MERIT_GPU` / `MERIT_RUNTIME` / `MERIT_SIF_DIR` / `MERIT_HF_CACHE` /
  `MERIT_WORK`, which `run.sh` takes when the `EGORAG_` ones are unset.
- Models downloaded into the cache on first use: `lmms-lab/EgoGPT-7b-EgoIT-EgoLife` (with its Whisper large-v3
  encoder in `speech_encoder/`), `google/siglip-so400m-patch14-384`, and the OpenCLIP ViT-B-32 text encoder
  (about 25 GB together).
- EgoGPT needs one 48 GB GPU: its peak was 23.2 GB, and on a 24 GB RTX A5000 the first clip ran out of memory.
  About 6 s a clip on an RTX A6000 (12 min per hour of video). Upstream's loader opens a `gloo` process group on
  port 12356, so run one caption job per machine.

On our own clusters, a virtualenv: `bash baselines/egorag/env/setup_env.sh <venv dir>` (Python 3.10 or 3.11),
then `PY=<venv dir>/bin/python bash baselines/egorag/run_egorag.sh ...` with `ffmpeg` and `patch` on the path and
`CUDA_HOME` set to a CUDA 12 toolkit.

## What the paid stages cost

`epic/estimate_api.py --video <V> --captions <V>_30sec.json --bank_file <V>_questions.json` counts the calls from
the real captions and upstream's prompts (outputs are assumed lengths, written in the script). Per video, build:
one GPT-4o call per 10 min of video, one DeepSeek call per hour, one GPT-4o call for the day. Per question about
6 GPT-4o calls: a summary of all captions since the last full hour (the largest: it grows with the time into the
hour), the day, the time range, evidence for each of 3 retrieved clips, the answer. On P05-20240425-201444
(27 min, 59 questions) that is 352 calls, 525k input tokens, about $1.60 at $2.50 / $10 per million tokens
(OpenAI's gpt-4o list price), $0.03 a question; the build is a few cents. Scaled to batch10 (598 questions):
about $20. Upstream regenerates the since-the-hour summary for every question, also for questions asked at the
same second; that is kept as released.

## What comes back (in the Hugging Face dataset)

Per video, at `egorag/egogpt_gpt4o/<video>/` in
[morph-graphs/epic-morph-results](https://huggingface.co/datasets/morph-graphs/epic-morph-results):
- the memory: `<video>_30sec.json` (captions), `<video>_l1_10min.json`, `<video>_l2_1h.json`, `<video>_l3_day.json`
  (the Chroma index is rebuilt from the captions when missing, in `work/index/`);
- `answers_<bank>.json.gz`: one row per question in bank order, keyed by the bank's `key` (plus `qhash`), with the
  chosen option (`response`; `none` when the reply held no letter), `evaluate`, the cutoff, the time range the LLM
  chose, the retrieved clips in video seconds, the evidence cards, `version` and the `memory_hash` the answer was
  made from (a row from another version or memory is redone);
- `api_usage.jsonl`: one line per paid call (which function, the model id the API returned, prompt and
  completion tokens; no text, no key);
- `runs.jsonl`: one line per finished stage (commits of this repo, upstream and epic-morph, the patch's hash, the
  model ids asked for, per returned model id the calls and tokens of the stage, torch and transformers versions,
  GPUs, seconds).
