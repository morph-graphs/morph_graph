# baselines/egorag: EgoRAG (EgoButler) on EPIC-Morph

[EgoRAG](https://github.com/EvolvingLMMs-Lab/EgoLife) is the retrieval half of EgoButler, the baseline system of
EgoLife (Yang et al., CVPR 2025, arXiv 2503.03803; code under the S-Lab License 1.0, non-commercial; the EgoGPT
folder says Apache-2.0). EgoGPT captions every 30 s clip from video and audio; the captions are indexed by
sentence and summarised at 10 min, 1 h and day level; a question is answered by letting an LLM pick a time range
from the summaries, retrieving the 3 best-matching caption sentences in it, extracting evidence from those clips'
captions and answering from the evidence.

**This port runs the method as published: its own models, not our local backbones.** That means paid API calls
for everything after the captions, so those steps run only when explicitly allowed (below).

| step | model, as published | where it runs |
|---|---|---|
| caption per 30 s clip (1 fps frames + audio) | EgoGPT-7b, `lmms-lab/EgoGPT-7b-EgoIT-EgoLife` (EgoIT-99K + EgoLife day 1) | local GPU |
| sentence index | OpenCLIP ViT-B-32 `laion2b_s34b_b79k` text encoder (Chroma's default embedding function) | local, CPU |
| 10 min and day summaries | GPT-4o (`call_gpt4`) | **paid API** |
| 1 h summaries | DeepSeek-R1 (`call_deepseek`) | **paid API** |
| day / time-range choice, evidence extraction, answer | GPT-4o (`call_gpt4`); the paper: "the final response is universally generated by GPT-4o" | **paid API** |

## Layout

| path | what |
|---|---|
| `EgoLife/` | upstream [EvolvingLMMs-Lab/EgoLife](https://github.com/EvolvingLMMs-Lab/EgoLife) at `7a97157`, unpatched (a clone for now; to become a submodule) |
| `epic/prepare_clips.py` | one HD-EPIC video -> 30 s clips with audio (448 px) and the clip list, in EgoLife's clock |
| `epic/caption_clips_egogpt.py` | EgoRAG's memory, step 1: an EgoGPT caption per clip (upstream's wrapper and prompt) |
| `epic/build_memory.py` | step 2: the Chroma index (upstream `create_database_from_json`), then the summaries (upstream `gen_event`, paid) |
| `epic/run_qa.py` | answers one video's questions of a bank (upstream `RagAgent.query`, `extract_evidence`, `get_answer`; paid); writes `answers_<bank>.json.gz` |
| `epic/estimate_api.py` | counts the paid calls and tokens of a video's build and questions, without calling anything |
| `run_egorag.sh` | one video, one stage (prep, build, estimate, qa, upload, all) |
| `env/` | the environment, pinned: `requirements.txt`, `setup_env.sh` |
| `../merit/epic/prepare_epic.py` | (MERIT's) the bank -> EgoLifeQA question rows, reused here |
| `../common/hf_results.py` | (shared) upload a video's results to the Hugging Face dataset, or fetch its memory |

There is one arm, `egogpt_gpt4o`, the paper's configuration. No Docker image yet.

## Running

```bash
bash baselines/egorag/env/setup_env.sh <venv dir>      # Python 3.11, CUDA 12.1 wheels; ffmpeg on PATH at run time
export PY=<venv dir>/bin/python EPIC_MORPH_DIR=<epic-morph checkout>
bash baselines/egorag/run_egorag.sh build    P05-20240425-201444 egogpt_gpt4o                  # captions + index, then stops (exit 4)
bash baselines/egorag/run_egorag.sh estimate P05-20240425-201444 egogpt_gpt4o batch10_agree2   # calls and tokens, none made
# with the paid endpoints (keys in the environment only):
export EGORAG_PAID_API=1 AZURE_API_KEY=... AZURE_API_ENDPOINT=... AZURE_DEEPSEEK_KEY=... AZURE_DEEPSEEK_ENDPOINT=...
bash baselines/egorag/run_egorag.sh build P05-20240425-201444 egogpt_gpt4o                     # the summaries
bash baselines/egorag/run_egorag.sh qa    P05-20240425-201444 egogpt_gpt4o batch10_agree2
```

EgoGPT needs one 48 GB GPU: on a 24 GB RTX A5000 the first clip ran out of memory (the 7B model in fp16 plus
Whisper large-v3 and SigLIP, about 30 frames and 30 s of audio per clip). Its checkpoint names the Whisper encoder as `./large-v3.pt`, which is in the model
repo's `speech_encoder/` folder; the caption script loads from there. That encoder imports `deepspeed`, which on a
GPU machine refuses to import without a CUDA toolkit: set `CUDA_HOME` (with `bin/nvcc`). Upstream's loader opens a `gloo` process
group on port 12356, so run one caption job per node.

**The paid steps.** `build` stops after the index and `qa` does not start unless `EGORAG_PAID_API=1` and
upstream's endpoint variables are set: `AZURE_API_KEY` + `AZURE_API_ENDPOINT` (the chat completions URL of a
GPT-4o deployment) and, for `build`, `AZURE_DEEPSEEK_KEY` + `AZURE_DEEPSEEK_ENDPOINT` (DeepSeek-R1 on Azure AI).
Only upstream's Azure branches run as released: `call_gpt4`'s `OPENAI_API_KEY` branch calls
`openai.ChatCompletion` (removed in the openai 1.x it pins, and it names `gpt-4`), and `call_deepseek`'s
`DEEPSEEK_API_KEY` branch indexes the response object like a dict (and names `deepseek-chat`). Using the OpenAI
or DeepSeek APIs directly needs a small patch to `egorag/utils/util.py` in a fork. `estimate` gives the calls,
tokens and a cost at the list prices written in `epic/estimate_api.py`; outputs are assumed lengths there.

**The memory is question-independent.** Captions, index and summaries depend only on the video. Per video, in
`results/egogpt_gpt4o/<video>/` (`EGORAG_OUT`): `<video>_30sec.json` (captions), `<video>_l1_10min.json`,
`<video>_l2_1h.json`, `<video>_l3_day.json`, then `answers_<bank>.json.gz` (one row per question, keyed by the
bank's `key`, with the chosen option, the time range the LLM chose, the retrieved clips in video seconds, the
evidence cards, `version` and `memory_hash`), `api_estimate*.json` and `runs.jsonl`. The Chroma index is rebuilt
from the captions when missing (`work/index/`). `upload` puts the folder at `egorag/egogpt_gpt4o/<video>/` in
[morph-graphs/epic-morph-results](https://huggingface.co/datasets/morph-graphs/epic-morph-results).

## Where the port differs from upstream, and why

Upstream's code is used unpatched; these are the adapter's choices.

- **One video is one EgoLife day starting at 10:00:00.** EgoRAG works in EgoLife's clock (`DAYn`, `HHMMSSFF`) and
  only handles 8-digit times (it reads the hour from the first two digits and asks the LLM for `[\d{8}]`), so
  video second 0 is `DAY1 10000000`. The LLM sees these clock times; answers record video seconds. With one day,
  the day level is trivial: the LLM is still asked for the day, as upstream does.
- **Streaming.** A question asked at `t_ask` is asked at clock(floor(t_ask)), as in the MERIT port. Upstream
  already uses only hour summaries that ended by then and summarises the later captions (up to the question)
  itself. The time range the LLM then returns is not checked upstream; here every retrieval is also limited to
  clips that ended by the question time, and the returned clips are asserted to be.
- **Retrieval query.** EgoLifeQA questions carry hand-written `keywords`, which upstream embeds as the query.
  EPIC-Morph has none: the question text is used.
- **Audio.** Upstream's EgoGPT wrapper slices the audio with the `HHMMSSFF` integers as seconds, which gives an
  empty slice (silence) for every clip. The paper captions from video and audio, so the clip's own audio is
  passed (`caption_clips_egogpt.py --audio silent` gives the released behaviour).
- **Captions through a file.** Captions are written to JSON and indexed with `create_database_from_json`
  (upstream's "Method 1"), not straight into Chroma, so they are a memory file and resumable.
- **Evidence from captions.** `main.py` calls `extract_evidence(..., modality="text")`: the LLM reads the
  retrieved clips' captions. The `video` modality (EgoGPT watches the clip again) is not what the released
  pipeline runs.
- **Failures.** Upstream drops a question it fails on (its accuracy is over the rest) and answers at random
  after an API error. Here a failed question is retried three times and then stays unanswered (`qa` exits 2;
  rerun), so every question of the bank is counted.
- **No blind stage**: the method has no local answer model to probe.
